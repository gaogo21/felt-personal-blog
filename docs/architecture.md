# 内容与页面的数据边界

公开页使用同源 `/api/public/v1`，管理页使用 `/api/admin/v1`。原有 hash 路由与动效仍由 dist/app.js 挂载；dist/data.js 负责请求、取消和字段转义，正文 HTML 只接收后端白名单结构生成的结果。标题、说明、项目正文等普通字段在客户端转义。管理后台是 Razor 入口与本地 JavaScript 表单，Tiptap 只负责结构化编辑，不保存登录凭据。

## 发布边界

ArticleDraft 是工作草稿，ArticleRevision 是一次发布快照；Article.PublishedRevisionId 指向当前公开版本。保存草稿只改 draft。发布先检查文章和草稿版本，再验证启用专栏、非空结构化正文与就绪媒体，创建 revision 并更新公开指针。历史版本恢复复制到 draft，公开指针不动。公开查询只读取 Published 状态及其快照，不接受客户端指定任意历史版本。

项目同样有 DraftJson 与 PublishedJson；公开项目只读取发布 JSON。随记复用文章实体，Kind=Life。知识库章节只关联已有文章，公开目录自动排除未发布内容。站点设置保存首页介绍、推荐、画廊顺序和关于内容；专栏与章节各有显式顺序。

## 写入一致性

所有内容写入、媒体引用变化、worker 状态提交与备份捕获共享 PostgreSQL 事务级 advisory lock。对单管理员博客选择串行写入，降低恢复后基础系统的并发复杂度；多实例同样遵守锁。保存要求 If-Match，与数据库版本一起检查；需要幂等的创建、发布和状态操作要求 UUID Idempotency-Key。相同键/请求复用原响应，键/内容不同返回冲突。清空资源会使旧响应失效，防止重放历史正文。

公开聚合查询在 repeatable-read 事务里完成，避免同时读到不同发布版本。Cookie 会话验证和登录计数使用独立边界，备份排除身份信息。媒体工具不持有数据库锁执行，但以租约令牌提交结果。

## 媒体与删除

上传原件在私有目录，依据声明 SHA-256 校验后入持久 Processing 队列。worker 领取三分钟租约，验证文件结构、官方 ClamAV 扫描、FFprobe 元数据与 FFmpeg 完整解码；图片重编码去除不受信任的元数据。结果只有令牌仍匹配时才能进入 Ready。工具失败最多重试三次；进程中断后租约过期可继续。过期的处理临时文件由持久清理器回收。

媒体引用记录 Draft、Revision、Column、Gallery、ProjectDraft/Published 等所有者。就绪文件仅向管理员或存在公开引用的访客提供；未发布上传不会得到公开访问权限。图片/视频正文由资源 ID 引用，不允许任意外部资源 URL。静态设计素材单独保留，后台不能删除。

回收站立即关闭公开内容；恢复曾发布文章得到 Withdrawn 状态，需要重新发布。永久清空文章删除草稿、历史版本、引用、章节关联，保留 ID/slug 墓碑，避免旧地址/幂等键混淆。媒体清空先让数据库状态不可交付，再由 worker 删除文件。

## 可维护性范围

新数据库使用一个完整初始迁移，不能冒充缺失的旧迁移序列。源码基础和管理表单是本次新建；16 份可复用历史正文的原始哈希保留在恢复清单中。当前模型面向一个个人博客管理员的内容维护，未加入多人协作审批、评论、搜索全文索引或外部对象存储；这些不在当前页面业务闭环中。
